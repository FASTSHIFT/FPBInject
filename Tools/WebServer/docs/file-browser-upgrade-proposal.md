# 文件浏览器体验升级方案（v2）

## 1. 现状分析

### 1.1 当前实现

| 功能 | 文件 | 浏览目标 | 体验评价 |
|------|------|---------|---------|
| PC 文件浏览器 | `filebrowser.js` + `modals.html` | 主机文件系统 | 基本可用，缺少元信息 |
| 设备文件传输 | `transfer.js` + `sidebar_transfer.html` | 设备文件系统（串口） | 功能完整，缺少右键菜单和拖拽移动 |

### 1.2 js-fileexplorer 方案失败总结

尝试引入 cubiclesoft/js-fileexplorer 后发现以下问题：

- **视觉风格不兼容**：库的 UI 是为独立页面设计的（彩色精灵图图标、宽工具栏、网格布局），与 VSCode 暗色侧边栏风格差距太大
- **CSS 覆盖困难**：201 个 CSS 规则，DOM 结构复杂，覆盖越多越像打地鼠
- **无列表模式**：只有图标网格视图，不适合侧边栏的窄空间
- **侧边栏嵌入效果差**：工具栏、路径栏、状态栏占用大量空间，留给文件列表的区域很小

**结论**：第三方文件管理器库不适合嵌入到 VSCode 风格的 UI 中。应该在现有手写代码基础上增量改进。

### 1.3 现有代码的优势

- 已经和 VSCode 主题完美融合（使用 CSS 变量）
- 侧边栏布局紧凑，空间利用率高
- 多选（Ctrl/Shift）、键盘快捷键（F2/Delete）已实现
- 拖拽上传（文件和文件夹）已实现
- SSE 进度流、CRC 校验、取消等传输功能完善

### 1.4 缺失的功能

| 功能 | PC 文件浏览器 | 设备文件浏览器 |
|------|-------------|--------------|
| 右键上下文菜单 | ❌ | ❌ |
| 拖拽移动（列表内） | N/A | ❌ |
| 文件大小/时间列 | ❌ | 仅大小 |
| 面包屑导航 | ❌ | ❌ |
| 搜索/过滤 | ❌ | ❌ |

## 2. 新方案：增量改进现有代码

### 2.1 设计原则

- **不引入第三方文件管理器库**，在现有代码上增量添加功能
- **复用项目已有的 UI 组件**（codicon 图标、VSCode CSS 变量、quick-commands 的右键菜单模式）
- **保持侧边栏紧凑布局**，不增加额外 UI 元素

### 2.2 Phase 1：右键上下文菜单（P0）

参考 `quick-commands.js` 的 `qcContextMenu` 实现模式：

**菜单项**：
- 上传文件 / 上传文件夹
- 下载（仅选中文件时可用）
- 新建文件夹
- 重命名（仅单选时可用）
- 删除

**改动**：
- `transfer.js`：`contextmenu` 事件监听
- `sidebar_transfer.html`：菜单 HTML
- `locales/*.js`：菜单项翻译

### 2.3 Phase 2：拖拽移动（P1）

列表内拖拽文件到文件夹实现移动（通过 `rename` API）：

- 列表项添加 `draggable` 属性
- 文件夹项作为 drop target
- 拖拽时半透明，目标文件夹高亮
- drop 时调用 `renameDeviceFile(srcPath, destDir + '/' + fileName)`

### 2.4 Phase 3：PC 文件浏览器增强（P2）

- 后端 `/api/browse` 增加 `size`/`mtime` 字段
- 列表项显示文件大小和修改时间
- 面包屑导航（可点击路径段）
- 隐藏文件切换

### 2.5 Phase 4：搜索和排序（P3）

- 设备文件列表顶部搜索框（客户端过滤）
- 点击列标题排序

## 3. 不变的部分

- 不引入第三方文件管理器库
- 不改变现有的 VSCode 风格 UI
- 不改变串口传输协议和 API
- 保留所有现有功能
